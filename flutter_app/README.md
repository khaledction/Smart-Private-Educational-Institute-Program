# 🖥️ معهدّي — تطبيق سطح المكتب (Flutter Desktop-First)

النموذج الأولي القابل للتشغيل لنظام إدارة المعاهد الذكي — **Windows أولًا** بنفس الواجهات العصرية المطلوبة في الوثيقة.

> **الإصدار الحالي: v3.7**
> الجديد في هذه النسخة:
> - ربط **شاشة طلب التسجيل** بقاعدة بيانات **SQLite محلية** على Windows
> - حفظ دائم لطلبات التسجيل والانتظار والاعتماد/الرفض
> - تحميل البيانات التجريبية تلقائيًا إلى القاعدة أول مرة
> - استمرار سياسات v3.6 المالية داخل الواجهات

## التشغيل بعد هذه النسخة
```bash
cd flutter_app
flutter pub get
flutter run -d windows
```

> لأننا أضفنا طبقة قاعدة بيانات محلية، هذه النسخة تحتاج **تحميل حزم جديد مرة واحدة فقط**.

## ما أصبح محفوظًا فعليًا
في النسخة الحالية، تم ربط **وحدة التسجيل والانتظار** بقاعدة بيانات SQLite محلية وتشمل:
- الطلاب (خيارات التسجيل)
- المواد
- المدرسين
- المجموعات المتاحة للتسجيل
- طلبات التسجيل
- قوائم الانتظار
- سجل تدقيق محلي لعمليات التسجيل

## مكان قاعدة البيانات المحلية
تُنشأ قاعدة البيانات تلقائيًا في مجلد المستندات الخاص بالمستخدم داخل مجلد:
```text
maehdi/
```
وباسم:
```text
maehdi_registration.db
```

## ما يعرضه النموذج الآن
| الشاشة | الحالة |
|--------|--------|
| لوحة القيادة | تعمل + تعرض عدد طلبات التسجيل والانتظار من القاعدة المحلية |
| التسجيل والانتظار | **مرتبطة بقاعدة بيانات فعلية** |
| الدورات | تعمل على Mock Data + منطق مالي v3.6 |
| المدرسون | تعمل على Mock Data + أثر التعويضات |
| المحاسبة | تعمل على Mock Data + دفتر ثلاثي وسياسات مالية |
| التقارير | تعمل على Mock Data |

## لماذا استخدمنا SQLite مباشرة الآن؟
لأن الهدف الحالي هو:
1. تقليل عدد الحزم الإضافية
2. الحصول على **حفظ دائم سريع**
3. ربط أول شاشة حقيقية بقاعدة بيانات محلية
4. جعل الانتقال إلى Drift لاحقًا أسهل بعد تثبيت منطق الجداول

## الخطوة التالية بعد نجاح التشغيل
1. توسيع نفس طبقة SQLite إلى:
   - الطلاب
   - الدورات
   - المدرسين
2. أو نقل الطبقة إلى Drift إذا قررنا ذلك
3. ثم الطباعة PDF والنسخ الاحتياطي المحلي
